# Frontend AGENTS.md

## 1. 목적과 적용 범위

이 문서는 frontend/에서 작업하는 Frontend Agent의 실행 규칙을 정의한다. 루트 AGENTS.md를 우선하며, 상위 보안·아키텍처·Active Plan 규칙을 완화하거나 무효화하지 않는다.

## 2. 작업 전 확인

- 제품 코드 구현·버그 수정 및 Harness 실행의 범위와 완료 조건은 Active Plan을 따른다.
- 구조와 상태 규칙은 FRONTEND.md를 따른다.
- UI·UX·접근성 기준은 DESIGN.md를 따른다.
- API 계약 확인이 필요한 경우 backend/API.md를 참고한다.
- 기능 요구사항은 관련 Product Spec 또는 Design Doc을 따른다.

## 3. 작업 범위

- frontend/만 수정한다.
- Backend, DB 스키마, Harness, 루트 정책 문서는 직접 수정하지 않는다.
- API 변경이 필요하면 백엔드 코드를 임의로 수정하지 않고 계약 변경 필요사항을 보고한다.
- 관련 없는 화면 정리, 전역 스타일 변경, 의존성 교체를 함께 수행하지 않는다.

## 4. 구현 원칙

- 구조와 상태 관리 규칙은 FRONTEND.md를 따른다.
- UI·UX와 접근성 규칙은 DESIGN.md를 따른다.
- API 계약과 다른 응답 구조를 임의로 확정하지 않는다.
- API 오류를 성공 데이터나 빈 데이터로 위장하지 않는다.
- 컴포넌트는 하나의 주요 책임을 가진다.
- 민감정보를 클라이언트 코드, 저장소, 로그에 노출하지 않는다.

## 5. 검증과 보고

- 구현 후 적용 가능한 타입 검사, 정적 분석, 테스트, 빌드를 실행한다.
- 결과는 변경 내용, 사용자 동작, 주요 상태(로딩/오류/권한), 접근성, API 불일치 여부와 함께 보고한다.
- 완료 조건을 충족하지 못한 경우 남은 문제를 명시한다.
