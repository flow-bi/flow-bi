# 일정 및 알림 설계

## 목적

일정, 회의실 예약, 알림, AI 비서 사이에 걸쳐 있는 연동 정책을 한 문서에서 관리한다.

Product Spec은 각 기능이 제공해야 하는 요구사항과 범위를 설명하고, 이 문서는 기능들이 서로 연결될 때 따르는 정책과 책임 범위를 설명한다.

- `docs/product-specs/meeting-room.md`

## 설계 대상

- 회의실 예약과 일정 연결
- 회의실 예약 생성 시 일정 생성
- 회의실 예약 수정 시 일정 갱신
- 회의실 예약 취소 시 일정 및 알림 처리
- 일반 일정 삭제 시 취소 상태와 이력 보존

## 공통 설계 원칙

- 회의실 예약과 캘린더 일정은 서로 연결하여 관리한다.
- 회의실 예약으로 생성된 일정의 회의실 관련 정보는 회의실 예약을 기준으로 관리한다.
- 회의실 예약 생성, 수정, 취소 시 연결된 일정에도 동일한 변경 사항을 반영한다.
- 일반 일정의 생성, 수정, 삭제는 캘린더 기능에서 처리한다.
- 일반 일정 삭제는 물리 삭제가 아니라 취소 상태 전환으로 처리한다.
- 알림 생성과 상태 관리는 알림 기능에서 담당한다.
- AI 비서는 알림 데이터를 직접 생성하지 않고 일정 및 알림 정보를 조회하여 사용자에게 안내한다.

## Calendar 공개·변경·감사 정책

### 공개 정책

- 일정 조회 권한은 일반 일정에서는 일정 유형, 작성자, 허용된 참석자·명시적 사용자 공유 대상, 연결된 팀·프로젝트와 현재 사용자 소속을 기준으로 판정한다. 회의실 예약 연결 일정은 아래 예약 예외를 따른다.
- 일반 `PERSONAL`/`PRIVATE` 일정은 작성자에게만 공개하며, 다른 사용자 참석자·명시적 사용자 공유 대상·팀·프로젝트 대상을 갖지 않는다. (`CAL-11-R1`, `CAL-11-R2`)
- 팀 일정은 연결된 팀 소속 사용자, 참석자와 명시적 사용자 공유 대상에게 공개한다.
- 프로젝트 일정은 연결된 프로젝트 참여자, 참석자와 명시적 사용자 공유 대상에게 공개한다.
- 명시적 사용자 공유 대상은 참석 여부와 별도로 관리하며 참석 인원에 포함하지 않는다.
- 일반 개인 일정에 과거 데이터로 참석자·명시적 사용자 공유 관계가 남아 있어도 등록자 외 조회 권한 근거로 사용하지 않는다. 승인 없는 Migration으로 관계를 일괄 삭제하지 않으며, 등록자가 Calendar에서 수정·저장할 때 빈 관계로 정리한다. (`CAL-11-R10`)
- 회의실 예약 연결 일정은 일반 개인 일정 제한의 예외다. 예약 기능이 예약자·참석자 관계를 생성·수정·조회하고 연결 일정에 동기화하며, Calendar 상세에서는 참석자를 확인할 수 있지만 Calendar에서 직접 수정·취소할 수 없다. (`CAL-11-R9`)
- 존재하지 않거나 현재 사용자에게 공개할 수 없는 일정은 동일한 안전한 결과로 처리하여 일정 존재 여부를 노출하지 않는다.

### 변경 정책

- Calendar MVP에서 일반 일정 수정·취소는 해당 일정의 등록자만 수행할 수 있다.
- 회의실 예약으로 생성된 일정은 Calendar에서 직접 수정·취소하지 않고 회의실 예약 관리 흐름을 사용한다.
- UI의 수정·취소 버튼 노출 여부는 보안 통제가 아니며 서버에서 소유권과 관리 주체를 다시 검증한다.
- 인증 Principal 대신 요청 Body나 경로로 전달된 사용자 ID를 변경 주체로 신뢰하지 않는다.

### 감사 정책

- 중요한 일반 일정 생성·수정·취소는 변경 주체, 시각, 일정 식별자와 결과를 추적할 수 있어야 한다.
- 감사 기록에는 일정 제목, 상세, 위치, 참석자, 공유 대상과 같은 업무 내용이나 불필요한 개인정보를 포함하지 않는다.
- 일반 일정 취소의 세부 감사 이벤트와 결과값은 결정 4와 `backend/API.md`의 Calendar 계약을 따른다.

## 결정 1. 회의실 예약 생성 시 일정도 함께 생성한다.

### 결정 내용

회의실 예약이 생성되면 연결된 일정도 함께 생성하고 캘린더에 표시한다.

생성되는 일정에는 다음 정보를 반영한다.

- 일정 제목
- 예약 날짜
- 시작 시간
- 종료 시간
- 회의실 정보
- 참석자
- 회의 상세 설명
- 일정 등록자

일정 위치는 예약된 회의실 이름을 기준으로 자동 설정한다.

### 이유

`requirements.md` FR-021은 회의실 예약 시 일정이 자동 생성되어 캘린더에 표시되어야 한다고 정의한다.

`database.md`도 `rooms_reservations`가 `schedules.schedule_id`를 참조하여 예약과 일정을 연결한다고 설명한다.

### 영향 범위

- 회의실 예약 생성
- 연결 일정 생성
- 캘린더 일정 조회
- 일정 상세 조회
- 예약과 일정의 식별 관계

### 관련 Product Spec

- `docs/product-specs/meeting-room.md`
- `docs/product-specs/calendar.md`

## 결정 2. 회의실 예약 수정 시 연결된 일정도 함께 수정한다.

### 결정 내용

회의실 예약이 수정되면 연결된 일정의 회의실 예약 관련 정보도 함께 갱신한다.

함께 갱신하는 정보는 다음과 같다.

- 일정 제목
- 예약 날짜
- 시작 시간
- 종료 시간
- 회의실 정보
- 참석자
- 회의 상세 설명

예약 회의실이 변경되면 일정 위치도 변경된 회의실 이름을 기준으로 갱신한다.

참석자가 변경되면 연결된 일정의 참석자 목록도 동일하게 갱신한다. 다만 참석자 변경으로 일정의 공개 범위가 자동 변경되지는 않는다.

### 수정 책임

회의실 예약 정보는 회의실 예약 기능을 기준으로 수정한다.

캘린더에서는 연결된 예약 일정을 조회할 수 있지만 회의실, 예약 날짜, 예약 시간 등 회의실 예약 관련 정보의 수정은 회의실 예약 수정 기능을 통해 처리한다.

일반 일정의 제목, 설명 등 회의실 예약과 관계없는 속성을 캘린더에서 수정할 수 있는지는 각 화면의 구현 범위에 따른다.

### 이유

`requirements.md` FR-022는 회의실 예약 정보 수정 기능을 정의한다.

`database.md`는 일정 시간이 변경되면 회의실 예약 시간도 함께 연동되어야 한다고 설명한다. 예약과 일정의 정보 불일치를 방지하기 위해 회의실 예약 관련 정보는 동일한 기준으로 갱신한다.

### 영향 범위

- 회의실 예약 수정
- 연결된 일정 수정
- 캘린더 조회 결과
- 참석자 정보
- 회의실 위치 정보
- 예약 중복 검증

### 관련 Product Spec

- `docs/product-specs/meeting-room.md`
- `docs/product-specs/calendar.md`

## 결정 3. 회의실 예약 취소 시 연결된 일정과 알림도 취소 처리한다.

### 결정 내용

회의실 예약이 취소되면 연결된 일정도 취소 상태로 변경한다.

취소된 일정은 이력 보존을 위해 물리적으로 삭제하지 않으며 일반 캘린더 조회에서는 기본적으로 표시하지 않는다.

예약 또는 일정에 연결된 발송 예정 알림은 취소 상태로 변경하여 더 이상 발송되지 않도록 처리한다.

### 일정 처리

- 회의실 예약은 취소 상태와 취소 시점을 저장한다.
- 연결된 일정도 취소 상태로 보존한다.
- 취소된 일정은 기본 캘린더 조회 대상에서 제외한다.
- 예약 및 일정 데이터는 이력 확인을 위해 물리적으로 삭제하지 않는다.

### 알림 처리

- 아직 발송되지 않은 알림은 취소 상태로 변경한다.
- 이미 발송된 알림은 삭제하거나 회수하지 않는다.
- 예약 관련 알림이 이미 발송된 경우 예약자와 참석자에게 예약 취소 안내를 추가로 제공한다.

### 이유

`requirements.md` FR-023은 회의실 예약 취소 기능을 정의한다.

`database.md`는 예약 취소 시 `rooms_reservations.cancelled_at`으로 취소 시점을 관리한다고 설명한다.

예약과 일정이 연결되어 있으므로 취소된 예약이 유효한 일정으로 계속 표시되거나 관련 알림이 계속 발송되지 않도록 처리해야 한다.

### 영향 범위

- 회의실 예약 취소
- 연결 일정의 상태
- 캘린더 표시 여부
- 일정 시작 전 알림
- 회의실 예약 알림
- AI 비서의 예정 일정 안내

### 관련 Product Spec

- `docs/product-specs/meeting-room.md`
- `docs/product-specs/calendar.md`
- `docs/product-specs/notification.md`
- `docs/product-specs/ai-assistant.md`

## 결정 4. 일반 일정 삭제는 취소 상태로 보존한다.

### 결정 내용

캘린더에서 일반 일정을 삭제하면 일정과 연결 데이터를 물리적으로 삭제하지 않고 일정 상태를 `CANCELED`로 변경한다.

취소 시각과 취소 주체를 함께 기록하며, 취소된 일정은 일반 캘린더 목록과 상세 조회에서 기본적으로 제외한다. 등록자가 이미 취소한 동일 일정에 삭제를 다시 요청하면 추가 상태 변경 없이 성공으로 처리한다.

회의실 예약으로 생성된 연결 일정은 이 정책의 직접 삭제 대상이 아니다. 캘린더는 회의실 예약 취소 흐름을 사용하도록 안전한 오류를 반환하고, 연결 일정의 취소는 결정 3을 따른다.

### 권한과 조회

- 캘린더 MVP에서는 일반 일정 등록자만 해당 일정을 취소할 수 있다.
- 인증되지 않은 요청은 거부한다.
- 존재하지 않는 일정과 요청자에게 노출할 수 없는 일정은 동일한 안전한 결과로 처리해 존재 여부를 노출하지 않는다.
- 취소된 일정의 상세, 공유 대상과 참석자 관계는 이력 확인을 위해 보존한다.
- 취소된 일정의 사용자 복구 기능은 현재 범위에서 제공하지 않는다.

### 감사와 후속 처리

- 취소 감사 이벤트에는 변경 주체, 시각, 일정 식별자와 결과만 기록하고 일정 상세나 개인정보를 기록하지 않는다.
- 캘린더 MVP의 일반 일정 취소는 알림 생성·취소를 직접 구현하지 않는다.
- 향후 알림 기능은 보존된 `CANCELED` 상태를 기준으로 발송 예정 알림을 취소할 수 있다.

### 이유

물리 삭제를 피하면 일정 상세와 공유·참석 관계의 참조 무결성과 감사 가능성을 유지할 수 있다. 기본 조회에서 취소 일정을 제외하면 사용자가 기대하는 삭제 결과를 제공하면서 네트워크 재시도에도 안전한 멱등 동작을 제공할 수 있다.

### 영향 범위

- 일반 일정 삭제 API
- 일정 상태와 취소 감사 정보
- 캘린더 목록 및 상세 조회
- 일정 공유 대상과 참석자 관계
- 향후 일정 취소 알림

### 관련 Product Spec

- `docs/product-specs/calendar.md`
- `docs/product-specs/notification.md`

## 결정 5. 알림은 사용자 알림 정책을 따른다.

### 결정 내용

일정 시작 전 리마인드 알림과 회의실 예약 관련 알림은 사용자의 알림 사용 여부, 알림 시간 및 알림 종류 설정을 따른다.

다만 예약 생성, 변경 및 취소 결과처럼 사용자가 반드시 확인해야 하는 정보는 사용자 설정과 관계없이 서비스 내부 알림으로 제공할 수 있다.

### 알림 종류

초기 알림 종류는 다음과 같이 구분한다.

- 일정 시작 전 알림
- 일정 변경 알림
- 일정 취소 알림
- 회의실 예약 완료 알림
- 회의실 예약 변경 알림
- 회의실 예약 취소 알림

사용자 설정 화면에서는 다음과 같이 묶어서 제공할 수 있다.

- 일정 리마인드
- 일정 및 예약 변경 알림
- 회의실 예약 결과 알림

### 알림 제공 채널

알림은 서비스 내부 알림함과 화면 내 알림으로 제공한다.

다음 채널은 현재 범위에서 제외한다.

- 이메일
- 문자 메시지
- 모바일 푸시
- 외부 메신저

### 회의실 예약 알림 대상

회의실 예약 생성, 수정 및 취소 알림은 다음 사용자에게 제공한다.

- 예약자
- 참석자

일정 시작 전 리마인드 알림은 각 사용자의 알림 설정에 따라 예약자와 참석자에게 제공한다.

### 이유

`requirements.md` FR-026~FR-028은 알림 사용 여부, 일정 시작 전 알림 시간 및 알림 종류 설정을 정의한다.

`requirements.md` FR-035는 사용자가 설정한 알림 정책에 따라 알림을 제공해야 한다고 정의한다.

### 영향 범위

- 일정 시작 전 리마인드
- 일정 변경 및 취소 알림
- 회의실 예약 생성, 변경 및 취소 알림
- 사용자별 알림 설정
- AI 비서의 알림 안내

## 결정 6. AI 비서는 일정과 알림 정보를 안내한다.

### 결정 내용

AI 비서는 알림 데이터를 직접 생성하지 않는다.

일정 및 알림 기능에서 생성한 데이터를 조회하여 사용자의 예정 일정과 관련 알림을 자연어로 안내한다.

AI 비서는 일반 일정과 회의실 예약으로 생성된 일정을 모두 안내할 수 있다.

### 제공 범위

AI 비서는 다음 정보를 안내할 수 있다.

- 오늘 예정된 일정
- 가까운 일정
- 일정 시작 전 리마인드
- 회의실 예약 일정
- 일정 또는 예약 변경 정보
- 일정 또는 예약 취소 정보

### 제공 방식

AI 비서의 일정 및 알림 제공 방식은 다음으로 제한한다.

- AI 비서 대화 응답
- 대시보드의 오늘 일정 요약

별도 푸시 알림과 알림함 데이터 생성은 알림 기능에서 담당한다.

### 이유

`requirements.md` FR-034는 AI 비서가 예정된 일정 알림을 제공할 수 있어야 한다고 정의한다.

FR-035는 사용자가 설정한 알림 정책에 따라 알림을 제공해야 한다고 정의한다.

알림 생성 책임과 AI 안내 책임을 분리하여 동일한 알림이 중복 생성되거나 기능 간 책임이 겹치지 않도록 한다.

### 영향 범위

- AI 비서의 일정 안내
- 회의실 예약 일정 안내
- 사용자 알림 정책 반영
- 대시보드 일정 요약
- 일정 및 알림 데이터 조회

## 상태 관리 기준

### 회의실 예약 상태

회의실 예약의 저장 상태는 다음과 같이 관리한다.

- `RESERVED`: 정상 예약
- `CANCELED`: 취소된 예약

예약 예정, 사용 중, 사용 완료 상태는 예약 시작·종료 시간과 현재 시간을 기준으로 화면에서 계산한다.

### 연결 일정 상태

회의실 예약으로 생성된 일정은 다음 상태를 가질 수 있다.

- `ACTIVE`: 정상 일정
- `CANCELED`: 취소된 일정

### 일반 일정 상태

일반 일정은 다음 상태를 가진다.

- `ACTIVE`: 정상 일정
- `CANCELED`: 사용자가 삭제하여 취소된 일정

`CANCELED` 전환 시 취소 시각과 취소 주체를 기록한다. 취소된 일반 일정은 물리 삭제하지 않고 기본 캘린더 및 상세 조회에서 제외한다.

### 알림 상태

알림은 다음 상태를 가질 수 있다.

- `SCHEDULED`: 발송 예정
- `SENT`: 발송 완료
- `CANCELED`: 발송 취소
- `FAILED`: 발송 실패

## 미확정 사항

- 회의실 예약과 연결된 일정의 일부 일반 속성을 캘린더 화면에서 직접 수정할 수 있는 범위
- 일정, 예약 및 알림 처리 중 일부 작업이 실패했을 때 데이터 정합성을 복구하는 방식
- 서비스 내부 알림의 보관 기간과 읽음 처리 정책
