# 작업 계획: global-layout-01

## 1. 기본 정보

### 사용자 요청

사이드바와 헤더를 포함한 서비스 전체 레이아웃을 구현한다.

### 작업 목적

개별 기능 화면이 일관된 구조 안에 배치될 수 있도록 공통 헤더, 사이드바, 본문 영역으로 구성된 반응형 애플리케이션 셸을 제공한다. 헤더에는 확정된 전역 레이아웃 요구사항에 따라 기업명과 로그인한 사용자 이름을 표시하고, 사이드바의 구체적인 메뉴와 라우팅을 확정하지 않은 상태에서도 후속 화면이 콘텐츠를 조립할 수 있는 구조를 만든다.

### 작업 유형

- feature

### 관련 설계 문서

- Product Spec: `docs/product-specs/global-layout.md`
- Design Doc: `docs/design-docs/core-beliefs.md`
- Architecture: `ARCHITECTURE.md`
- 기타 참고 문서: `frontend/FRONTEND.md`, `frontend/DESIGN.md`, `CONVENTIONS.md`, `docs/quality/quality-model.md`

#### 수정 금지 경로

- `backend/`

- `docs/quality/`

#### 구현 항목

- [ ] Red 단계에서 기업명과 사용자 이름이 있는 공통 헤더, 접근 가능한 사이드바 내비게이션 영역, 본문 Landmark, 모바일 사이드바 열기·닫기 동작을 사용자가 관찰 가능한 실패 컴포넌트 테스트와 `frontend/cypress/e2e/global-layout/` 브라우저 테스트로 먼저 작성하고 의도한 이유로 실패한 결과를 실행 기록에 남긴다.
- [ ] Green 단계에서 헤더·사이드바·본문을 책임별 React 컴포넌트로 구성하고, `App`이 기업명·사용자 이름·사이드바 콘텐츠·본문 콘텐츠를 조립하는 최소 구현으로 작성한 테스트를 통과시킨다.
- [ ] 데스크톱에서는 헤더와 사이드바가 본문과 함께 안정적으로 배치되고, 작은 화면에서는 접근 가능한 이름을 가진 버튼으로 사이드바를 열고 닫을 수 있도록 반응형 레이아웃을 구현한다.
- [ ] 모바일 사이드바를 `Escape` 키로 닫을 수 있게 하고 닫힌 뒤 열기 버튼으로 포커스가 돌아오도록 하며, 현재 위치와 주요 영역을 시맨틱 Landmark와 Heading으로 식별할 수 있게 한다.
- [ ] 헤더 왼쪽에는 기업명, 오른쪽에는 로그인한 사용자 이름을 표시하고 검색 입력은 추가하지 않는다.
- [ ] 역할 기반 색상 토큰과 Product Spec의 Sky Theme 후보색 `#EDF1F6`을 사용해 기본 배경·Surface·텍스트·테두리·포커스 상태를 구성하되, 컴포넌트에 임의 Hex 값을 반복하지 않는다.
- [ ] Refactor 단계에서 레이아웃 책임과 스타일 중복을 정리한 뒤 컴포넌트 테스트와 Cypress 테스트를 다시 실행하고 결과를 실행 기록에 남긴다.

#### 검증 항목

- [ ] 관련 Vitest 컴포넌트 테스트로 헤더의 기업명·사용자 이름, 검색창 부재, Landmark 구조, 모바일 사이드바의 열기·닫기·`Escape`·포커스 복귀를 검증한다.
- [ ] `npm run test:unit -- --run`을 `frontend/`에서 실행해 관련 단위·컴포넌트 테스트가 통과하는지 확인한다.
- [ ] `npm run test:e2e -- --spec cypress/e2e/global-layout/**/*.cy.ts`를 `frontend/`에서 실행해 데스크톱과 모바일 뷰포트에서 헤더·사이드바·본문 배치와 키보드 상호작용을 검증한다.
- [ ] `npm run typecheck`를 `frontend/`에서 실행해 컴포넌트 입력과 조립 구조의 타입 오류가 없는지 확인한다.
- [ ] 구현 문제로 검증이 실패하면 최대 3회까지 수정 후 이 Task의 검증만 다시 실행하고, 계속 실패하면 우회하지 않고 원인과 남은 문제를 기록한다.
