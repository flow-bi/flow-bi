# 인증 Product Spec

## 기능 목적

관리자가 발급한 계정을 사용하는 임직원이 사번과 비밀번호로 로그인하고, Redis에 저장된 서버 세션을 통해 인증된 사용자만 그룹웨어를 이용할 수 있도록 한다.

## 상세 요구사항

### 포함한 요구사항

- 사용자는 사번과 비밀번호를 이용하여 로그인할 수 있어야 한다. (FR-009)
- 사용자는 로그아웃할 수 있어야 한다. (FR-010)
- 사용자는 별도로 회원가입하지 않으며 관리자가 발급한 사번과 임시 비밀번호를 사용한다.
- 임시 비밀번호로 로그인한 사용자는 일반 기능을 이용하기 전에 비밀번호를 변경해야 한다.
- 사용자는 마이페이지에서 현재 비밀번호를 검증한 뒤 비밀번호를 변경할 수 있어야 한다.
- 로그인 상태는 Redis를 공용 Session Store로 사용하는 서버 세션으로 관리한다.
- 동일 사용자의 여러 브라우저 또는 기기 로그인을 허용하고 사용자별 세션을 식별할 수 있어야 한다.
- 로그인한 사용자만 서비스를 이용할 수 있어야 한다. (NFR-001)
- 비밀번호는 복호화할 수 없는 단방향 해시로만 저장해야 한다. (NFR-002)

### 제외한 요구사항

- 직원 등록, 조회, 수정, 삭제와 임시 비밀번호 발급·초기화 실행 화면은 `admin.md`에서 다룬다.
- 개인정보 조회 및 수정과 일반 비밀번호 변경 화면은 `my-page.md`에서 다룬다.
- 기기별 세션 조회·종료 화면과 모든 기기 로그아웃 UI는 현재 범위에 포함하지 않는다.
- 외부 인증 제공자, 기업 SSO, JWT 기반 브라우저 인증은 현재 범위에 포함하지 않는다.

## 화면 구성 요소

- 로그인 화면
  - 사번 입력
  - 비밀번호 입력
  - 로그인 실행 요소
  - 로그인 성공·실패 상태와 일반화된 오류 메시지
- 비밀번호 변경 필요 화면
  - 새 비밀번호 입력 및 확인
  - 비밀번호 변경 실행 요소
  - 변경 완료 전 일반 기능 접근 제한
- 인증 후 공통 화면
  - 로그아웃 실행 요소

## 인증 및 세션 흐름

1. 사용자가 사번과 비밀번호를 입력한다.
2. 백엔드가 사번으로 인증 정보를 조회하고 비밀번호 해시를 검증한다.
3. 인증에 성공하면 변경되지 않는 내부 `userId`를 Principal로 하는 Spring Security 인증과 HttpSession을 생성한다.
4. Spring Session이 세션을 Redis에 저장하고 브라우저에는 불투명한 세션 식별자만 Cookie로 전달한다.
5. 이후 요청에서 백엔드는 Redis 세션을 조회해 인증된 사용자와 권한을 확인한다.
6. 로그아웃하면 현재 세션을 무효화한다.

사번은 로그인 Credential로만 사용한다. 인증 이후 세션과 도메인 관계의 사용자 식별 기준은 내부 `userId`이다.

## 비밀번호 변경 흐름

### 최초 로그인

1. 관리자가 임시 비밀번호를 발급하고 인증 정보의 `mustChangePassword` 상태를 활성화한다.
2. 사용자가 사번과 임시 비밀번호로 로그인한다.
3. 시스템은 로그인 세션을 생성하되 비밀번호 변경 화면과 변경·로그아웃 기능을 제외한 일반 기능 접근을 제한한다.
4. 사용자가 새 비밀번호를 설정하면 비밀번호 해시를 갱신하고 `mustChangePassword` 상태를 해제한다.
5. 현재 세션은 유지하고 동일 사용자의 다른 세션은 모두 무효화한다.

### 사용자의 일반 비밀번호 변경

1. 현재 로그인 사용자의 기존 비밀번호를 검증한다.
2. 새 비밀번호 정책을 검증한 뒤 새 비밀번호 해시를 저장한다.
3. 현재 세션은 유지하고 동일 사용자의 다른 세션은 모두 무효화한다.

### 관리자 비밀번호 초기화

1. 권한이 있는 관리자가 대상 사용자의 비밀번호를 임시 비밀번호로 초기화한다.
2. 대상 사용자의 `mustChangePassword` 상태를 활성화한다.
3. 대상 사용자의 모든 세션을 즉시 무효화한다.
4. 대상 사용자는 임시 비밀번호로 다시 로그인하고 최초 로그인 변경 흐름을 따른다.

## 세션 정책

- 세션에는 `userId`, Spring Security Authentication/SecurityContext, 역할 또는 권한, 생성·최근 접근·만료 정보 등 인증 유지에 필요한 최소 정보만 저장한다.
- 비밀번호, 비밀번호 해시, 임시 비밀번호와 변경 가능한 일반 프로필 정보는 세션에 저장하지 않는다.
- 역할 또는 주요 권한이 변경되면 이전 권한이 남지 않도록 해당 사용자의 모든 세션을 무효화한다.
- 세션이 만료되거나 Redis에서 제거되면 사용자는 다시 로그인해야 한다.
- Session Cookie에는 `HttpOnly`, `Secure`, `SameSite` 정책을 적용하며 사용자 정보를 포함하지 않는다.

## 확정된 기능 결정

- 브라우저 인증은 JWT가 아니라 Redis를 Session Store로 사용하는 서버 세션 방식을 사용한다.
- 사번과 비밀번호로 로그인하며, 인증 이후에는 내부 `userId`로 사용자를 식별한다.
- 동일 사용자의 여러 동시 세션을 허용하고 사용자별로 세션을 조회·무효화할 수 있게 한다.
- 사용자 비밀번호 변경 시 현재 세션만 유지하고 다른 세션은 무효화한다.
- 관리자 비밀번호 초기화와 역할·주요 권한 변경 시 대상 사용자의 모든 세션을 무효화한다.
- 모든 일반 기능은 인증을 요구하며, 비밀번호 변경 필요 상태에서는 허용된 제한 기능만 접근할 수 있다.

## 확정된 기능 결정의 근거

- `requirements.md` FR-009, FR-010은 로그인과 로그아웃을 요구한다.
- `requirements.md` NFR-001은 로그인 사용자만 서비스 이용 가능해야 한다고 정의한다.
- `requirements.md` NFR-002는 비밀번호를 안전하게 저장해야 한다고 정의한다.
- Notion의 「구현 준비」 결정은 서버가 로그인 상태를 즉시 통제하고 수평 확장된 서버가 상태를 공유할 수 있도록 Redis 기반 서버 세션을 채택한다.
- 같은 결정은 비밀번호 변경, 관리자 초기화, 권한 변경 시 사용자별 세션 무효화 정책을 정의한다.

## 인수 조건

- 올바른 사번과 비밀번호로 로그인하면 Redis에 서버 세션이 생성되고 보안 속성이 적용된 Session Cookie가 발급된다.
- 잘못된 자격정보로 로그인하면 계정 존재 여부를 구분하지 않는 오류로 실패하고 세션이 생성되지 않는다.
- 인증되지 않은 사용자는 로그인에 필요한 공개 경로를 제외한 그룹웨어 기능에 접근할 수 없다.
- `mustChangePassword`가 활성화된 사용자는 비밀번호 변경과 로그아웃 외 일반 기능에 접근할 수 없다.
- 사용자가 비밀번호를 변경하면 현재 세션은 유지되고 같은 사용자의 다른 세션은 즉시 사용할 수 없게 된다.
- 관리자가 비밀번호를 초기화하거나 역할·주요 권한을 변경하면 대상 사용자의 모든 기존 세션을 사용할 수 없게 된다.
- 로그아웃하거나 세션이 만료되면 해당 세션으로 보호된 기능에 접근할 수 없다.
- 세션과 로그에 평문 비밀번호, 비밀번호 해시, 임시 비밀번호가 포함되지 않는다.

## Scope Decision

- In Scope: 로그인, 로그아웃, 최초 로그인 비밀번호 변경 강제, 일반 비밀번호 변경 정책, 인증 사용자 접근 제한, Redis 기반 서버 세션, 사용자별 세션 무효화, 비밀번호 단방향 해시 저장.
- Out of Scope: 직원 계정 CRUD UI, 프로필 정보 수정, 기기별 세션 관리 UI, 외부 인증 제공자와 SSO, 외부 API·모바일·서비스 간 토큰 인증.
- Moved: 직원 계정 생성과 관리자 비밀번호 초기화 화면은 `admin.md`, 일반 비밀번호 변경 화면은 `my-page.md`로 이동한다.
