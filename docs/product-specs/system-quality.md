# 시스템 공통 품질 Product Spec

## 문서 목적

특정 화면이나 도메인 하나가 소유하지 않는 서비스 공통 비기능 요구사항을 정의한다. 기능별 응답 시간, 보안과 같은 전용 요구사항은 해당 Product Spec과 정책 문서에서 관리한다.

## 상세 요구사항

### 가용성 (NFR-005)

- 서비스는 24시간 사용 가능해야 한다.
- 목표 가용률, 측정 기간, 계획된 점검 제외 여부와 장애 복구 기준은 배포 환경이 확정된 뒤 운영 Plan에서 구체화한다.
- 측정 기준이 확정되기 전에는 24시간 사용 가능 요구사항을 최종 충족으로 판정하지 않는다.

### PC 및 Mobile (NFR-006)

- 각 Product Spec이 정의한 핵심 사용자 흐름은 PC와 Mobile에서 수행할 수 있어야 한다.
- 지원 Browser, 최소 화면 폭과 Device Matrix는 관련 Frontend Active Plan에서 정의한다.
- 기능별 검증 범위는 해당 Product Spec과 Active Plan에 기록한다.

### 확장성 (NFR-007)

- 새 기능은 기존 도메인의 내부 구현을 무분별하게 침범하지 않아야 한다.
- 순환 의존과 공통 모듈로의 비즈니스 규칙 집중을 허용하지 않는다.
- 기능 간 연동은 소유 도메인과 참조 도메인의 책임을 분리하고 공개 계약을 통해 연결한다.

## 요구사항 소유 경계

- 인증과 비밀번호 보호(NFR-001, NFR-002): `auth.md`
- 캘린더 응답 시간(NFR-003): `calendar.md`
- AI 응답 시간(NFR-004): `ai-assistant.md`
- 가용성, PC·Mobile, 확장성(NFR-005~NFR-007): 이 문서
- 공통 품질 판정 방식과 증거 형식: `docs/quality/quality-model.md`

## 미확정 사항

- 배포 환경과 목표 가용률
- 계획된 점검의 가용성 측정 포함 여부
- 지원 Browser와 Device Matrix
- 확장성 정량 지표와 부하 기준
