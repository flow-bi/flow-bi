# 일정 관리 Product Spec

## 기능 목적

사용자가 개인, 팀, 프로젝트 일정을 월간/주간/일간 캘린더에서 조회하고 등록, 수정, 삭제할 수 있도록 한다.

## 상세 요구사항

### 포함한 요구사항

- 사용자는 월 단위로 일정을 조회할 수 있어야 한다. (FR-011)
- 사용자는 주 단위로 일정을 조회할 수 있어야 한다. (FR-012)
- 사용자는 일 단위로 일정을 조회할 수 있어야 한다. (FR-013)
- 사용자는 일정을 등록할 수 있어야 한다. (FR-014)
- 일정 제목, 위치, 날짜, 시간, 참석 인원 정보를 입력할 수 있어야 한다. (FR-015)
- 개인 일정, 팀 일정, 프로젝트 일정 중 하나를 선택할 수 있어야 한다. (FR-016)
- 사용자는 등록한 일정을 수정할 수 있어야 한다. (FR-017)
- 사용자는 등록한 일반 일정을 삭제할 수 있어야 한다. 삭제는 물리 삭제가 아니라 취소 상태 전환으로 처리한다. (FR-018)
- 캘린더의 한 달 범위 조회와 화면 표시가 합의된 측정 환경에서 3초 이내에 완료되어야 한다. (NFR-003)
- 캘린더 핵심 흐름은 PC와 Mobile에서 수행할 수 있어야 한다. (NFR-006)
- 첫 화면은 월간 캘린더이다.
- 월간/주간/일간 캘린더를 선택할 수 있다.
- 월간 및 주간 캘린더의 한 주는 일요일부터 토요일 순서로 표시한다.
- 날짜 클릭 시 해당 날짜의 일정이 일간 보기와 같은 24시간 시간축을 사용하는 우측 패널에 표시된다.
- 날짜별 우측 패널은 패널 바깥 영역을 클릭하면 닫힌다.
- 특정 일정 클릭 시 일정 상세가 모달로 표시된다.
- 일정 추가는 모달로 제공한다.
- 일정 추가 진입 버튼은 캘린더 상단에 표시한다.
- 일정 추가 항목은 일정 타입, 제목, 날짜, 시작 시간, 종료 시간, 하루종일, 위치, 일정 유형, 공개 범위, 색상 라벨, 참석자, 상세 설명이다. 단, 일반 `PERSONAL`/`PRIVATE` 일정에는 다른 사용자 참석자 또는 명시적 사용자 공유 대상 입력을 제공하지 않는다. (`CAL-11-R1`)
- 일정 수정 폼은 일정 추가 폼과 같은 필드 순서, 레이블·입력 표현, 반응형 날짜·시간 배치를 사용한다. 팀·프로젝트 대상도 원시 ID가 아닌 이름 기반 체크박스 목록으로 확인·수정하며 Loading·Empty·Error 상태를 제공한다. 기존 개인 일정 및 회의실 관리 일정 정책은 유지한다. (`CAL-12-R1`~`CAL-12-R5`)
- 일정 유형별 기본 공개 범위를 적용한다.
- 사용자는 일정별로 하나의 색상 라벨을 선택할 수 있다.
- 팀·프로젝트 일정의 참석자는 사내 사용자 목록에서 이름 또는 사번으로 검색하여 추가·제거할 수 있다. 기존 참석자와 검색 결과에는 사용자 ID 원문 대신 사용자 이름을 표시한다. (`CAL-11-R4`)
- 참석자 검색은 Loading·Empty·Error·Permission 상태를 구분하고, 검색·선택 결과에는 `userId`, `displayName` 외 개인정보를 표시하거나 저장하지 않는다. (`CAL-11-R5`)
- 참석 인원은 선택된 참석자와 등록자 참석 여부를 기준으로 자동 계산하며, 등록자는 중복 계산하지 않는다. (`CAL-11-R6`)
- 등록자의 참석 여부는 별도로 지정할 수 있다.

### 제외한 요구사항

- 회의실 예약 자체는 `meeting-room.md`로 이동한다.
- AI를 통한 자연어 일정 생성은 `ai-assistant.md`로 이동한다.
- 일정 알림 정책 설정은 `my-page.md`로 이동한다.

## 화면 구성 요소

- 월간 캘린더
- 주간 캘린더
- 일간 캘린더
- 캘린더 보기 전환 요소
- 날짜별 일간 일정 우측 배너
- 일정 상세 모달
- 일정 추가 모달
  - 일정 타입
  - 제목
  - 날짜
  - 시작 시간
  - 종료 시간
  - 하루종일
  - 위치
  - 일정 유형
  - 공개 범위
  - 색상 라벨
  - 팀·프로젝트 일정용 참석자 검색, 추가 및 개별 제거
  - 등록자 참석 여부
  - 참석 인원
  - 일정 상세 설명

일정 상세 모달은 참석 인원, 다른 참석자의 이름 목록 및 등록자 참석 여부를 별도로 표시한다. 다른 참석자가 없으면 빈 상태를 표시하며, 사용자 ID 원문은 표시하지 않는다. 생성·수정·상세의 검색 결과, 선택 목록 및 제거 버튼은 키보드와 Screen Reader로 식별·조작할 수 있고 Desktop 1280×800 및 Mobile 390×844에서 문서 가로 overflow가 없어야 한다. (`CAL-11-R7`, `CAL-11-R8`)

## 캘린더 표시 계약

- `CAL-05-R1`: 사용자가 캘린더 헤더의 `오늘`을 선택하면 현재 보기 단위는 유지하고, 기준 날짜를 캘린더에 주입된 `now()`의 로컬 날짜로 변경한다. 따라서 월간 보기에서는 오늘이 속한 달, 주간 보기에서는 오늘이 속한 주, 일간 보기에서는 오늘 날짜를 표시한다.
- `CAL-05-R2`: 오늘 이동은 기존 URL 상태 계약을 사용한다. URL에는 유지된 `view`와 오늘의 `date`를 함께 반영하며, 별도의 날짜 계산이나 시스템 시각 직접 참조로 URL 상태를 만들지 않는다.
- `CAL-05-R3`: 헤더 액션은 접근 가능한 이름을 가진 별도 영역으로 구성한다. 기간 이동 영역은 `이전`, `오늘`, `다음`을, 보기 선택 영역은 `월간 보기`, `주간 보기`, `일간 보기`를 포함한다. `일정 추가`는 두 제어 영역 밖의 주요 생성 액션이다.
- `CAL-05-R4`: `일정 추가`는 데스크톱과 모바일 모두에서 헤더 액션의 화면상 맨 오른쪽이자 키보드 탐색 순서의 마지막에 둔다.
- `CAL-05-R5`: 헤더 액션은 데스크톱과 390px 모바일 화면에서 줄바꿈 또는 적절한 정렬로 겹침과 문서 전체 가로 overflow를 방지한다.
- `CAL-05-R6`: 기간 이동, 보기 선택, 일정 생성 액션은 각각 접근 가능한 이름과 보이는 키보드 포커스 표시를 제공하고, 문서 읽기 및 키보드 탐색 순서는 기간 이동, 보기 선택, 일정 생성 순서로 유지한다.
- 기간 이동과 보기 선택은 중립 또는 선택 상태 스타일을 사용한다. 일정 생성만 주요 채움 스타일을 사용해 역할을 구분하며, 현재 선택된 보기는 생성 액션과 다른 선택 상태 스타일로 식별할 수 있어야 한다.
- 월간·주간·일간의 일정 항목은 색상 라벨을 `RED`, `PURPLE` 같은 원시 enum 이름으로 화면 또는 접근 가능한 이름에 표시하지 않는다. 제목, 일정 유형, 날짜·시간 텍스트로 일정을 식별할 수 있어야 하며, 색상만으로 일정의 의미·우선순위·상태를 전달하지 않는다.
- 월간·주간 일정 항목은 일정 제목과 공개 범위에 대응하는 `개인`, `팀`, `프로젝트` 레이블만 표시한다. 일간 시간표는 시간축 배치를 보완하기 위해 같은 정보에 읽기 쉬운 시간 범위를 추가한다.
- 일정 상세 모달의 제목은 일정 제목 자체를 사용하며 `상세` 같은 고정 접미사를 덧붙이지 않는다.
- 색상 라벨 `RED`, `ORANGE`, `YELLOW`, `GREEN`, `BLUE`, `PURPLE`은 각각 구분 가능한 일정 배경·테두리·텍스트 스타일로 표시한다. 알 수 없는 색상은 새로운 업무 의미를 부여하지 않는 읽기 가능한 중립 스타일로 표시한다.
- 저장·전송되는 시작·종료 시각의 ISO 8601 값은 변경하지 않고, 사용자 표시 직전에 `Asia/Seoul` 기준으로 변환한다. 단일 시각은 `2026년 8월 16일 09:00`, 같은 날의 시간 범위는 `2026년 8월 16일 09:00–10:00`, 날짜가 다른 범위는 양쪽에 년·월·일·시·분을 표시한다.
- 종일 일정은 시작 날짜를 `Asia/Seoul` 기준으로 `2026년 8월 16일 · 하루 종일`처럼 표시하며, 초·밀리초·ISO 구분자·UTC offset 원문은 노출하지 않는다.
- 캘린더 기능이 소유하는 생성·상세·수정·삭제/취소 확인·미저장 변경 확인 모달의 일반 닫기 컨트롤은 우측 최상단에 둔다. `×`를 사용하면 접근 가능한 이름은 `닫기`여야 하며, footer에는 등록·저장·수정·일정 취소·삭제·확인처럼 업무 의미가 있는 동작만 둔다. 단순 닫기용 footer 버튼은 두지 않는다.
- 일간 보기는 종일 일정 영역과 시간 일정 영역을 분리하고, 00:00부터 24:00까지의 세로 시간축에 시작 시각과 지속 시간이 대응되도록 일정 위치를 표시한다.
- 날짜별 우측 패널도 종일 일정 영역과 00:00부터 24:00까지의 세로 시간축을 사용하며, 패널 바깥 영역 선택 시 닫힌다.
- 일정 추가 모달의 체크박스와 레이블은 같은 행에서 세로 중앙 정렬한다.

## 데이터 흐름

1. 사용자가 캘린더 보기 단위를 선택한다.
2. 선택한 월, 주, 일 기준으로 사용자가 볼 수 있는 일정을 조회한다.
3. 날짜 선택 시 해당 날짜의 일정을 시간대에 맞춰 우측 패널에 표시한다.
4. 일정 선택 시 상세 정보를 모달에 표시한다.
5. 일정 등록 시 일정 유형에 따른 기본 공개 범위를 적용한다.
6. 팀·프로젝트 일정에서 사용자가 사내 사용자 검색으로 참석자를 추가·제거하면 선택된 목록과 등록자 참석 여부를 기준으로 참석 인원을 자동 계산한다.
7. 일반 `PERSONAL`/`PRIVATE` 일정은 등록자 전용이며 다른 사용자 참석자, 명시적 사용자 공유 대상, 팀·프로젝트 대상을 갖지 않는다. 생성·수정 요청에 `participantIds` 또는 `userTargetIds`가 하나라도 있으면 서버는 저장 전에 안정적인 Calendar 입력 오류로 거부하고 부분 변경을 남기지 않는다. (`CAL-11-R1`, `CAL-11-R2`)
8. 팀·프로젝트 일정의 유형을 `PERSONAL`로 변경하면 화면은 선택한 참석자와 명시적 사용자 공유 대상을 제거했음을 알리고, `participantIds`, `userTargetIds`, `teamTargetIds`, `projectTargetIds`를 모두 빈 배열로 저장 요청을 보낸다. (`CAL-11-R3`)
9. 일정 등록 시 기본 일정 정보와, 유형이 허용하는 공유 대상·참석자 정보를 함께 생성한다.
10. 일정 수정 또는 삭제 시 등록자 기준으로 변경 가능한 일정을 대상으로 처리한다.
11. 일반 일정 삭제 시 일정을 `CANCELED` 상태로 전환하고 취소 시각과 취소 주체를 기록한다.
12. 취소된 일정은 기본 캘린더 및 상세 조회에서 제외하며, 같은 등록자의 반복 삭제 요청은 성공으로 처리한다.
13. 회의실 예약으로 생성된 일정은 캘린더에서 직접 삭제하지 않고 회의실 예약 취소 흐름을 사용한다.
14. 회의실 예약으로 생성된 일정은 캘린더에 표시된다. Calendar 상세 모달에서는 예약 참석자를 확인할 수 있으나, Calendar 수정 화면에서는 직접 수정할 수 없다. (`CAL-11-R9`)
15. 회의실 예약과 일정의 상세 연동 정책은 `docs/design-docs/schedule-and-notification.md`를 따른다.

## 확정된 기능 결정

- 일정은 개인, 팀, 프로젝트 유형을 가진다.
- 일정은 제목, 시작/종료 일시, 등록자를 기본 정보로 가진다.
- 일정 상세 설명과 위치는 상세 정보로 관리한다.
- 팀·프로젝트 일정의 공유 대상은 사용자, 팀, 프로젝트 단위로 지정될 수 있다. 일반 `PERSONAL`/`PRIVATE` 일정은 등록자 전용이므로 사용자·팀·프로젝트 공유 대상 또는 다른 사용자 참석자를 지정할 수 없다. 등록자 참석 여부는 다른 사용자 참석자 추가와 구분되는 필드다. (`CAL-11-R1`, `CAL-11-R2`)
- 일정 유형과 공개 범위는 서로 다른 값으로 관리한다.
- 일정 유형별 공개 범위는 다음과 같다.
- 개인일정은 비공개이다.
- 팀일정은 팀공개이다.
- 프로젝트 일정은 프로젝트 공개이다.
- 색상 라벨은 일정별로 하나만 선택할 수 있다.
- 색상 라벨은 Red, Orange, Yellow, Green, Blue, Purple 중 하나를 선택한다.
- 색상 라벨은 일정의 시각적 구분을 위한 값이며 색상별 고정된 의미나 우선순위는 부여하지 않는다.
- 화면에서는 색상 라벨의 원시 enum을 노출하지 않고, 정적으로 정의된 배경·테두리·텍스트 스타일로만 표현한다. 알 수 없는 색상에는 중립적인 읽기 가능한 fallback을 사용한다.
- 월간·주간 일정 항목은 일정 제목과 공개 범위에 대응하는 한글 레이블로 간결하게 표시하고, 일간 시간표에만 시간 범위를 함께 표시한다.
- 일정 상세 모달의 접근 가능한 제목은 고정 접미사 없이 일정 제목과 동일하게 유지한다.
- 사용자에게 표시하는 일정 일시는 `Asia/Seoul` 기준의 년·월·일·시·분 형식을 사용하며, API와 URL의 ISO 8601 값은 그대로 유지한다.
- 캘린더 모달의 일반 닫기는 우측 최상단의 `닫기` 또는 접근 가능한 이름이 `닫기`인 `×`로 통일한다. footer는 업무 동작만 제공한다.
- 일간 보기는 종일 영역과 24시간 세로 시간축을 제공한다.
- 날짜별 우측 패널은 일간 보기의 시간 배치 규칙을 재사용하고 패널 바깥 클릭으로 닫을 수 있다.
- 일정 추가 버튼은 캘린더 헤더 영역에 둔다.
- 일정 추가 폼의 체크박스는 레이블 문구와 같은 행에서 중앙 정렬한다.
- 팀·프로젝트 일정의 참석자는 사내 사용자 검색으로 지정하고 이름으로 식별하며 개별 제거할 수 있다. 일반 `PERSONAL`/`PRIVATE` 일정에는 참석자 입력을 제공하지 않는다. (`CAL-11-R1`, `CAL-11-R4`)
- 상세 응답은 기존 `participantIds`를 유지하고 최소 참석자 객체 목록과 `attendeeCount`를 함께 제공한다. 참석 인원은 다른 참석자의 중복을 제거하고 등록자를 한 번만 포함해 계산한다. (`CAL-11-R6`)
- 등록자의 참석 여부는 별도로 지정할 수 있다.
- 등록자가 참석하는 경우 전체 참석 인원에 포함한다.
- 일반 일정 삭제는 물리 삭제 없이 `CANCELED` 상태로 보존하는 Soft Delete 방식으로 처리한다.
- 취소 시각과 취소 주체를 기록하며 일정 상세, 공유 대상과 참석자 관계는 감사와 이력 확인을 위해 함께 보존한다.
- 취소된 일정은 일반 캘린더 목록과 상세 조회에서 기본적으로 제외한다.
- 등록자가 이미 취소한 일반 일정에 삭제를 다시 요청하면 성공으로 처리하여 멱등성을 보장한다.
- 취소된 일반 일정의 사용자 복구 기능은 캘린더 MVP 범위에서 제공하지 않는다.
- 회의실 예약으로 생성된 일정은 캘린더에서 조회 가능해야 한다.
- 회의실 예약과 연결된 일정의 생성, 수정, 취소 정책은 `docs/design-docs/schedule-and-notification.md`를 따른다.
- 회의실 예약 연결 일정은 일반 개인 일정 제한의 대상이 아니다. 예약 기능은 예약자·참석자 연동을 계속 관리하며 Calendar는 상세 조회만 제공한다. (`CAL-11-R9`)
- 기존 일반 개인 일정의 참석자·사용자 공유 관계는 승인 없는 Migration으로 일괄 삭제하지 않는다. 이 관계는 등록자 외 조회 권한에 사용하지 않으며, 등록자가 수정·저장하면 새 계약에 맞게 빈 관계로 정리한다. (`CAL-11-R10`)

## 확정된 기능 결정의 근거

- `requirements.md` FR-011~018에서 캘린더 조회 및 일정 CRUD를 정의한다.
- `ui-ux-spec.md` 1-4에서 캘린더 화면, 배너, 모달, 입력 항목을 정의한다.
- `database.md`의 `schedules`, `schedules_details`, `schedule_targets`는 일정 기본 정보, 상세 정보, 공유 대상을 분리해 설명한다.
- 일정 유형과 공개 범위를 분리하여 일정의 소속 범위와 조회 가능 범위를 독립적으로 관리한다.
- 일정 유형별 기본 공개 범위를 설정하여 일정 등록 시 사용자가 매번 공개 범위를 지정하지 않아도 되도록 한다.
- 색상 라벨은 일정의 시각적 구분을 위한 기능이므로 시스템에서 색상별 의미를 강제하지 않는다.
- 참석 인원을 허용된 참석자 목록과 등록자 참석 여부에서 자동 계산하여 직접 입력한 인원수와 실제 참석자 목록이 불일치하는 문제를 방지한다.
- 일반 개인 일정의 잔존 관계를 Migration으로 제거하지 않고 조회 권한에서 제외하면 데이터 손실 없이 새 등록자 전용 정책으로 전환할 수 있다.
- 일반 일정을 물리 삭제하지 않고 취소 상태로 보존하여 감사 가능성과 참조 무결성을 유지하고, 기본 조회에서 제외해 사용자에게는 삭제된 것과 같은 결과를 제공한다.
- `database.md`는 회의실 예약이 일정과 연결되어 캘린더에 자동 추가된다고 설명한다.
- 회의실 예약과 일정의 생성, 수정, 취소 연동 정책은 `docs/design-docs/schedule-and-notification.md`에서 다룬다.

## Scope Decision

- In Scope: 캘린더 조회, 일정 상세 조회, 일정 등록/수정/삭제, 일정 유형 및 공개 범위, 색상 라벨, 팀·프로젝트 일정의 참석자 검색·지정, 참석 인원 자동 계산 및 이름 기반 상세 표시.
- In Scope: 일반 `PERSONAL`/`PRIVATE` 일정의 등록자 전용 공개·입력 제한과 기존 관계의 비파괴적 전환 정책.
- Out of Scope: 일반 개인 일정의 기존 참석자·공유 관계를 일괄 삭제·보정하는 Migration, 회의실 예약 참석자 정책 변경.
- Out of Scope: 회의실 목록/예약 현황, AI 자연어 처리, 알림 발송.
- Moved: 회의실 예약은 `meeting-room.md`, AI 일정 생성은 `ai-assistant.md`, 알림은 `notification.md`로 이동한다. 일정과 예약, 알림의 연동 정책은 `docs/design-docs/schedule-and-notification.md`로 이동한다.
