# Backend AGENTS.md

## 1. 목적과 적용 범위

이 문서는 `backend/`에서 작업하는 사람과 Backend Agent가 따라야 하는 영역 규칙을 정의한다. 루트 `AGENTS.md`를 구체화하며 상위 보안·아키텍처·Active Plan 규칙을 완화하지 않는다.

## 2. 작업 전 확인

- 제품 코드 구현·버그 수정 및 Harness 실행의 범위와 완료 조건은 Active Plan을 따른다.
- 구조와 계층 규칙은 `backend/BACKEND.md`를 따른다.
- API와 스키마 변경은 각각 `backend/API.md`, `backend/DB_SCHEMA.md`를 확인한다.
- 인증·인가·민감정보 변경은 `SECURITY.md`를 확인한다.
- 기능 요구사항은 관련 Product Spec 또는 Design Doc을 따른다.
- 문서와 요구사항이 충돌하면 스키마나 API를 임의로 확정하지 않는다.

## 3. 작업 범위

- Backend는 `backend/`만 수정한다.
- Frontend, Harness 및 루트 정책은 직접 수정하지 않고 변경 필요사항을 보고한다.
- 공개 API 또는 DB 스키마 변경은 관련 문서와 마이그레이션을 같은 Task에서 갱신한다.
- 승인되지 않은 의존성, 외부 서비스 또는 아키텍처 패턴을 도입하지 않는다.
- 범위 밖 문제는 기술 부채 또는 검토 대기 항목으로 기록한다.

## 4. 구현과 검증

- 구현과 버그 수정은 루트 `AGENTS.md`의 TDD 및 예외 규칙을 따른다.
- 도메인 규칙과 유스케이스의 실패 테스트를 제품 코드보다 먼저 작성한다.
- 권한·트랜잭션·DB 제약·동시성에 의존하는 규칙은 적용 가능한 통합 테스트를 포함한다.

기본 검증 명령은 다음과 같다.

```text
./gradlew spotlessCheck
./gradlew test
./gradlew build
```

실행할 수 없는 명령은 이유와 남은 위험을 보고한다.

## 5. 작업 보고

- 구현한 유스케이스와 관련 요구사항
- TDD 및 최종 검증 결과
- 변경한 API, 스키마와 마이그레이션
- 적용한 권한·트랜잭션·동시성 검증
- 미실행 검증, 남은 위험과 사람의 결정이 필요한 사항
